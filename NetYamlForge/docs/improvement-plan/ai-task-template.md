# AI実行タスクテンプレート

## 1. 目的

AIに依頼する際の入力品質を揃え、不要な往復と誤修正を減らす。

## 2. タスク記述テンプレート

以下をそのまま埋めて利用する。

```md
# Task
- タイトル: [Area] [目的] [制約]
- 種別: feat / fix / refactor / test / docs

## 背景
- 現在の問題:
- 発生箇所:
- 期待挙動:

## 対象範囲
- 対象ファイル:
- 対象機能:

## 非対象範囲
- 変更しないこと:

## 実装制約
- 互換性要件:
- パフォーマンス要件:
- セキュリティ要件:

## 完了条件
1. 〜
2. 〜
3. `dotnet build` 成功

## 検証手順
1. 実行コマンド:
2. 手動確認手順:

## 出力フォーマット
- 変更ファイル一覧
- 変更理由（要点）
- 検証結果
- 未対応項目
```

## 3. 良い依頼の例

```md
# Task
- タイトル: [UI] Filter Clear で picker 表示と hidden 値を同期クリアする
- 種別: fix

## 背景
- 現在の問題: Clear 実行後に hidden は空だが表示ラベル/チップが残る
- 発生箇所: Views/DynamicEntity/Index.cshtml, Views/Shared/_Layout.cshtml
- 期待挙動: hidden/display/chips がすべて同期してクリアされる

## 対象範囲
- 対象ファイル: 上記2ファイル
- 対象機能: filter clear と picker clear

## 非対象範囲
- DB スキーマ、コントローラのビジネスロジックは変更しない

## 完了条件
1. Clear 後、表示と送信値が一致
2. 既存の検索/ページング動作を維持
3. `dotnet build` 成功
```

## 4. 禁止事項（AI依頼時）

1. あいまいな目標（例: 「いい感じに改善」）
2. 対象範囲未指定での大規模改修依頼
3. 検証手順なしの実装依頼
4. 互換性要件なしのリファクタ依頼

## 5. 受け入れ基準（レビュー用）

1. 指定範囲外の変更がない
2. エラーハンドリングが悪化していない
3. 差分理由が明確
4. 検証結果が再現可能

# 品質ゲート定義

## 1. 目的

- マージ前に最低限満たすべき品質基準を固定化し、リグレッションを防止する。

## 2. 必須ゲート（全PR共通）

1. `dotnet build` が成功
2. 変更機能に対する手動確認手順を記載
3. 影響範囲を明記
4. ログ/エラーメッセージの悪化がない
5. ドキュメント影響の有無をPRに明記（`Documentation impact: Yes/No`）

## 3. 変更種別ごとの追加ゲート

### 3.1 設定/YAML変更

1. スキーマ整合性チェック
2. 対象エンティティの画面表示確認
3. 既存プロジェクト（最低1件）の非影響確認

### 3.2 Hook変更

1. Hookコンパイル成功
2. Before/After の期待挙動確認
3. 異常系メッセージ確認
4. トランザクション境界の確認

### 3.3 一覧/UI変更

1. フィルタ/ソート/ページングの回帰確認
2. Clear 動作確認（hidden/display/chips の同期）
3. 戻るURL（returnUrl）の保持確認

### 3.4 SQL/検索ロジック変更

1. 許可列バリデーション確認
2. 想定外入力の防御確認
3. 実行時間の劣化有無を確認

## 4. 推奨自動チェック

1. 将来的に `dotnet test` を必須化
2. 主要シナリオの統合テストを段階追加
3. 変更箇所に応じたスモークテスト自動実行

## 5. 手動回帰チェックリスト（最小）

詳細手順は `docs/improvement-plan/regression-checklist.md` を参照。

1. 一覧初期表示
2. 検索
3. フィルタ適用
4. フィルタクリア
5. 新規作成
6. 編集
7. 削除
8. 外部キー picker 選択/解除
9. 総件数表示（count=true）

## 6. マージブロック条件

以下のいずれかに該当した場合はマージ不可。

1. ビルド失敗
2. 必須確認結果の未記載
3. 重大回帰の未解消
4. ロールバック不能な変更で回避策が未記載

## 7. リリース前ゲート（週次/本番前）

1. 主要プロジェクト（例: chinook, blog, northwind-sqlite3-ops）でスモーク確認
2. Hookロード/コンパイルエラーが0件
3. 直近変更に対する既知不具合の再発チェック
4. CHANGELOG 反映

# 自動車ディーラー統合管理システム：要約・構造化仕様書

本ドキュメントは「自動車ディーラー統合管理システム 詳細仕様書」の内容を、開発および設計の視点から再構成・要約したものである。

## 1. プロジェクト概要

| 項目 | 内容 |
| :--- | :--- |
| **システム名** | 自動車ディーラー統合管理システム |
| **主要目的** | 販売、整備、部品、顧客、会計の一元管理による業務効率化と顧客満足度向上 |
| **主要ユーザー** | 販売員、整備士、部品担当、受付、経理、管理者 |
| **基盤** | Webベース（PC・タブレット対応） |

---

## 2. 機能モジュール構成

システムは以下の8つの主要モジュールで構成される。

1.  **顧客管理 (CRM)**: 基本情報、所有車歴、顧客区分管理
2.  **車両在庫管理**: 新車・中古車在庫、入出庫、ステータス追跡
3.  **販売管理**: 見積・契約・納車、支払・ローン管理
4.  **サービス・整備管理**: 予約・受付、作業指示、進捗管理、点検履歴
5.  **部品在庫管理**: 部品マスタ、発注・入庫、出庫（整備紐付け）
6.  **会計・請求管理**: 請求書発行、入金消込、売上集計
7.  **レポート・分析**: 部門別売上、作業実績、KPI分析
8.  **システム・マスタ管理**: 各種マスタ、権限設定、ログ管理

---

## 3. 主要データモデル概要

### 核心エンティティ
- **顧客**: 氏名、連絡先、区分
- **車両**: 車種、年式、走行距離、車体番号、在庫ステータス
- **契約**: 顧客・車両紐付け、金額、支払方法、納車予定日
- **サービス受付**: 作業内容、担当整備士、ステータス、実績時間
- **部品**: コード、在庫数、発注点、単価

---

## 4. 業務プロセスフロー（主要3系統）

### A. 販売契約プロセス
1.  **リード/顧客登録**: 顧客情報の入力
2.  **見積作成**: 車両選定、オプション・下取り・ローン計算
3.  **契約締結**: 契約書作成、車両ステータスを「受注済み」へ
4.  **納車準備・決済**: 入金管理、車検・登録手続き
5.  **納車**: 実納車、ステータスを「納車済み」へ、アフターフォロー開始

### B. サービス整備プロセス
1.  **受付/予約**: 顧客・車両特定、作業内容ヒアリング
2.  **作業指示**: 指示書発行、担当割当、必要部品引当
3.  **作業遂行**: 進捗記録（受付→作業中→完了）
4.  **精算**: 部品実績確定、請求書発行、入金確認
5.  **納車**: 引渡し、次回点検時期の自動算出

### C. 部品管理プロセス
1.  **在庫監視**: 在庫数と発注点の比較（アラート）
2.  **発注・入庫**: 仕入先への発注、入荷検収、在庫加算
3.  **出庫**: 整備作業での使用または単体販売による在庫減算

---

## 5. 技術・運用仕様

### 非機能要件
- **レスポンス**: 検索 2s以内 / 請求作成 3s以内
- **可用性**: 8:00–20:00 稼働保証
- **セキュリティ**: IP制限（VPN）、暗号化保存、全操作ログ

### 主要バッチ処理
- **月末在庫集計**: 在庫回転率算出、レポート生成
- **点検リマインダー**: 次回点検対象者への自動通知（毎日実行）
- **勤怠・有給管理**: 社員向け福利厚生・労務集計

### トランザクション設計
- **契約/納車**: 車両ステータス更新と契約/納車レコード作成を同一トランザクションで実行
- **部品出庫**: 在庫減算と整備実績登録の原子性を保証

## 6. 将来拡張：AI窓口システム (Vision)

AIを一次窓口として活用し、人間とのハイブリッド運用を目指す。

- **マルチチャネル対応**: LINE、Webチャット、音声IVRをAIで統合
- **自然言語理解 (NLU)**: インテント（意図）判定による自動振り分け（修理予約、見積依頼など）
- **対話管理**: コンテキストを維持した接客、推奨エンジンによる最適車種提案
- **エスカレーション**: AI判断不能時の人間担当者へのシームレスな引き継ぎ
- **データ駆動改善**: A/Bテストによる対話モデルの継続的最適化
